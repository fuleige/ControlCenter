# Controller Center 产品设计

> 状态：v1 已实施，后续按本文档迭代
> 版本：2026-09-10 / v1
> 范围：控制中心 Web、Control Plane、Node Agent；结果库继续作为独立服务，不纳入本期

## 1. 产品目标

Controller Center 是面向个人开发工作的多节点 Codex 对话与任务调度中心。产品首先保证：

1. 能快速选择节点并开始或继续对话。
2. 同时运行多个任务时，用户能看到全局状态并及时处理失败或等待操作的任务。
3. 对话只展示用户真正需要的内容：用户消息、Codex 回复、简洁进度和必要错误。
4. 浏览器刷新、网络闪断、Control Plane 或 Agent 重启后，不重复创建任务并尽可能恢复状态。
5. 桌面端、平板和移动 Web 使用同一套功能边界。

## 2. 明确不做

- 不提供代码 Diff 或代码变更审阅面板。
- 不展示详细命令、命令输出、推理文本、原始 App Server 事件和调试 JSON。
- 不建设独立审批中心。需要用户操作的任务在全局任务中心提示，具体操作回到对应对话内完成。
- 不建设复杂节点运维详情页；节点只保留选择、在线状态、重命名和必要异常提示。
- 不提供绕过 Codex 的远程 Shell。

## 3. 信息架构

### 3.1 桌面端

```text
┌────────节点栏────────┬──────会话栏──────┬────────────────对话区────────────────┐
│ 品牌 / 任务中心入口   │ 搜索 / 新建       │ 会话标题 / 设置入口                  │
│ 节点列表              │ 置顶与历史会话    │ 消息历史                            │
│                      │                  │ 简洁进度                            │
│ 设置入口              │                  │ [回到底部]                          │
│                      │                  │ [当前任务状态 / 中止本轮]            │
│                      │                  │ [附件][模型][思考] 输入框 [发送]     │
└──────────────────────┴──────────────────┴──────────────────────────────────────┘
```

### 3.2 移动端和平板窄屏

- 使用“节点 → 会话 → 对话”的单页分层导航，不压缩成三栏。
- 全局任务中心从状态入口进入右侧主内容区，桌面端只保留全局节点菜单，隐藏依赖当前节点的历史会话栏。
- 设置为全屏页面。
- 输入区固定在安全区上方，附件预览在输入框上方横向滚动。

### 3.3 全局快速切换

- 桌面端通过节点栏入口或 `Ctrl/Cmd + K` 打开，移动端通过顶部搜索图标打开。
- 在同一个轻量面板中按节点名称或会话名称搜索全部节点和跨节点历史会话。
- 空关键词只展示搜索提示，不请求或渲染历史会话；输入关键词后使用防抖执行服务端查询。
- 选择节点后进入该节点的新会话草稿；选择历史会话后自动切换所属节点并恢复会话。
- 从设置或任务中心点击当前节点返回工作台时，保留原来打开的会话；创建会话必须使用明确的“新建会话”入口。
- 快速切换不改变任务中心的信息架构，也不会创建新会话记录。

## 4. 节点栏

### 4.1 展开状态

每个节点只显示：

- 显示名称。
- 在线、离线或恢复中状态。
- 当前活动任务数 / 最大并发数。
- 平台简写作为次要信息。
- 启用 `--yolo` 的节点显示紧凑的“全权限”标识；普通节点不额外占用空间。
- 重命名入口。

不展示 Codex 版本、完整工作区和运行日志等详情。

### 4.2 折叠状态

折叠宽度保持为约 68–72px，并保留可操作的节点列表：

- 每个节点使用稳定的短标识：优先取显示名称的第一个中文字符，英文名称取前两个字母。
- 标识右下角显示在线状态点。
- 当前节点使用高亮边框和浅色背景。
- 点击标识立即选择节点，并打开该节点的新会话草稿。
- 鼠标悬停或键盘聚焦时显示完整节点名 Tooltip。
- 多个节点纵向排列；一个节点时仍保留一个明确可点击的标识。
- 若有任务等待操作，在对应节点标识右上角显示小徽标。
- 全权限节点在短标识边缘保留红色提示，即使侧边栏折叠也不能隐藏权限状态。

短标识只用于视觉识别，节点身份仍使用稳定 Node ID，名称重复不会影响选择。

### 4.3 重命名

- 使用节点卡片下方的小型编辑面板，不使用大字号弹窗。
- 明确说明“仅修改控制中心显示名称”，并展示 Agent 报告的本机名称。
- 输入框字号 11–12px，按钮分为次要“取消”和主要“保存”。
- 空白名称不可提交；长度上限 64 个字符。
- 保存失败保留用户输入并显示行内错误。

### 4.4 工作空间

工作空间是会话交给本地 Codex 使用的目录，例如 `/projects/app-a`。每个会话创建时必须绑定一个工作空间，绑定后不会随全局默认值变化；历史会话继续在原工作空间中执行。

每个节点的工作空间分为四类：

- 默认：始终是 Agent 进程的启动目录。Web 不能改名、迁移、停用、删除或另行指定默认项。
- 启动配置：来自 `AGENT_WORKSPACES`，由节点部署配置维护，Web 只读。
- Web 添加：管理员在设置中直接输入该节点的路径。
- 历史保留：Agent 更换启动目录或移除启动配置后，为仍有关联会话的旧目录保留；不再出现在新会话选择器中。

Web 添加路径时，Control Plane 向在线 Agent 发起验证。Agent 使用自身操作系统身份解析规范绝对路径，并确认路径存在、是目录且可读写；只有验证成功才持久化。系统不会创建目录，也不额外限制允许的根目录，因此可访问范围就是 Agent 运行用户的文件系统权限范围。创建会话、开始后续轮次和重试任务前必须重新验证，Agent 在调用 Codex App Server 前还会做最后一次本地检查。

路径迁移无论是否已有会话都必须明确二次确认。已经绑定会话的工作空间只能停用，不能删除；停用后历史仍可查看，但不能继续发起任务。未绑定会话的 Web 工作空间可以确认后删除。Agent 若从新的当前目录重启，新目录立即成为默认；仍被会话引用的旧默认目录保持原 ID 和路径作为历史记录。

同一规范路径中的任务按路径串行排队，即使存在历史工作空间别名也不会并发修改同一批文件；不同路径可在节点并发额度内并行。

### 4.5 节点权限模式

Agent 不传额外参数时使用 `workspaceWrite` 与正常审批流程。只有节点管理员在本机启动 Agent 时显式传入 `--yolo`，才会以 `approvalPolicy: never` 和 `dangerFullAccess` 启动 Codex App Server，并对新 Thread/Turn 重申相同策略。该选项是进程级配置，Web 只展示 Agent 上报的真实状态，不提供远程开关，避免控制中心把受限节点静默升级为全权限节点。

### 4.6 节点代理模式

Agent 只读取 Linux/macOS CLI 通用的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 与 `NO_PROXY`（含小写形式），不建设 Web 端代理配置，也不把代理地址或凭据上报中心。默认情况下，首次注册、WSS 控制通道、附件下载和 Codex 子进程都遵循这些环境变量。

显式传入 `--codex-proxy-only` 后，Agent 自身所有控制中心流量强制直连，但不修改自身环境变量，因此 Codex App Server 子进程仍继承原有代理配置。注册 CLI 与 Agent 是两个独立进程，需要分别传入该参数；未检测到代理环境变量时，两种模式等价。

## 5. 会话栏

### 5.1 展开状态

v1 提供以下基本管理功能：

- 新建会话。
- 按会话名称搜索，不检索用户消息、Codex 回复、代码或附件内容。
- 手动重命名。
- 置顶 / 取消置顶。
- 删除并二次确认。
- 按“全部、进行中、失败”筛选。

归档、标签、文件夹和批量操作暂不进入 v1。

### 5.2 折叠状态

- 保留一个始终可见的“＋”快捷按钮。
- 当前已选择节点时，点击立即创建本地新会话草稿；发送第一条消息前不写数据库。
- 未选择节点时按钮禁用，并通过 Tooltip 提示先选择节点。
- 保留历史会话数量的轻量标识，但不在窄栏显示会话标题。
- 点击窄栏的历史图标可重新展开会话栏。

## 6. 对话与进度信息

### 6.1 对话中展示

- 用户消息。
- Codex 回复，支持 Markdown、代码复制和公式。流式消息快照到达即重新渲染，兼容 `$...$`、`$$...$$`、`\(...\)` 与 `\[...\]`；公式闭合后无需等待整轮完成即可显示。
- 消息卡片直接展示正文，不再用“你 / Codex”标题单独占一行；消息时间保留在卡片悬停提示中。
- 当前任务的单行进度，例如：
  - 正在分析任务
  - 正在处理文件
  - 正在验证结果
  - 等待你的操作
  - 正在整理回复
- 完成、失败、停止等最终状态。
- 失败时展示经过整理的一句话错误和“重新发送”入口。
- 运行中的浮动状态条提供“中止本轮”；该操作结束当前 Turn，不承诺从中断点继续。
- 长对话首次读取最近 60 条消息，可按游标加载更早消息，并使用动态高度虚拟列表只挂载当前视口附近的消息；首次打开和刷新后定位到最新回复，用户主动上滑后停止自动跟随，点击“滑动到底部”恢复跟随。

### 6.2 不展示且不持久化

- 命令文本与命令输出。
- 文件 Diff。
- 推理过程和 reasoning delta。
- 原始 App Server payload。
- 工具调用的逐条开始、输出和完成事件。
- 仅用于调试的事件。

这不是前端隐藏策略。Agent 在进入耐久 Outbox 前完成事件分类，详细事件不发送到 Control Plane。

### 6.3 数据模型调整

当前回复依赖 `events` 表回放。目标模型改为：

- `messages`：持久保存 user / assistant 消息及流式聚合文本。
- `runs`：保存任务状态、简洁进度阶段、错误摘要和时间。
- `notifications`：保存全局任务中心需要提示的状态变化。
- `events`：不再作为产品对话数据源；仅保留必要的短期内部事件，默认关闭详细事件落库。

流式回复按固定时间窗口合并写入消息快照，避免每个 token 都写数据库。任务完成时强制刷新最终消息。

## 7. 输入区与附件

### 7.1 输入区

- 新会话始终显示工作空间选择器，即使节点只有一个可选项；默认选择该节点不可修改的默认工作空间，并按节点记住最近一次草稿选择。
- 历史会话不允许切换工作空间，标题栏持续显示它绑定的节点与工作空间。
- 模型和思考强度位于输入框内的底部工具栏。
- 选择器直接显示当前值，不额外展示“模型”“思考强度”文字标签；保留无障碍名称和悬停提示。
- 默认值来自设置；用户在会话中修改后，仅覆盖当前会话后续轮次。
- 输入草稿按“节点 + 会话”保存在浏览器本地，刷新后恢复。
- Enter 发送，Shift+Enter 换行；发送中仍允许追加指令。

### 7.2 上传文件与粘贴图片

支持：

- 文件选择器上传一个或多个文件。
- 拖拽文件到输入区。
- 从剪贴板粘贴图片。
- 发送前显示缩略图、文件名、大小、上传进度和移除按钮。
- 上传失败可以单独重试，不影响已经上传的其他附件。

推荐链路：

```text
Browser --分片上传--> Control Plane 临时附件库
        --发送消息时引用 attachmentId-->
Control Plane --鉴权下载指令--> Agent 本地附件缓存
Agent --校验 SHA-256 / 转换为 App Server 输入--> Codex
```

浏览器不能直接连接位于 NAT 后的 Agent。Control Plane 只保存临时附件，Agent 下载到独立缓存目录，不直接写入项目工作区。

安全要求：

- 文件名规范化，禁止路径穿越。
- 服务端校验实际大小、内容类型和 SHA-256。
- 附件下载使用单次、短时效令牌。
- 配置单文件、单消息和总存储配额。
- 会话删除和过期清理必须覆盖 Control Plane 与 Agent 两端缓存。

## 8. 设置界面

设置使用独立页面而不是临时弹窗，为后续扩展保留分类导航。

当前包含“对话默认值”和“工作空间”两个分类。

“对话默认值”包含：

- 默认模型。
- 默认思考强度。
- 无法匹配默认模型时的回退说明。
- 固定展示当前 Controller Center 版本号，便于确认 Web 更新是否生效。

“工作空间”按节点展示默认、启动配置、Web 添加及历史保留项，支持在线验证、添加、重命名、路径迁移、停用、恢复和未使用项删除；具体按钮按照工作空间来源和会话引用数收敛。

后续可增加：通知、附件、安全、外观和数据保留等分类。

默认值解析顺序：

```text
当前会话显式选择
  > 当前节点覆盖值（未来）
  > 全局偏好模型（节点支持时）
  > Agent 报告的本机默认模型
```

若全局偏好模型不在当前节点的模型目录中，自动回退到 Agent 默认模型，并在选择器中显示一次非阻塞提示，不阻止发送。

## 9. 全局任务中心

### 9.1 入口

- 桌面端在节点栏品牌区提供固定入口。
- 移动端在顶部栏提供固定入口。
- 徽标数字只统计“等待操作、失败、未读完成”。
- 任务中心使用独立主内容页面，不使用遮挡当前内容的弹窗；桌面端保留全局节点菜单，隐藏依赖单一节点上下文的历史会话栏。从任务记录可直接打开其所属节点和会话，点击节点则返回该节点的新会话工作区。

完成、失败或等待操作发生时，只有用户当时不在对应会话界面，才产生未读通知并增加徽标。用户正在查看对应会话时，状态直接在对话中呈现，不额外产生未读数字。进入对应会话后，其相关通知自动标记已读。

### 9.2 状态分组

- 进行中：queued、dispatching、running、recovering。
- 等待操作：waiting_approval。
- 已完成：completed，区分已读和未读。
- 失败：failed，区分已读和未读。
- 已停止：interrupted，不默认计入未读徽标。

每条记录展示节点、会话标题、对应 Run 最新 Codex 回复的前 120 个字符、状态和时间。点击后跳转到对应节点和会话；即使目标就是进入任务中心前查看的会话，也必须主动重新加载详情，不能停在恢复界面。

任务中心提供会话名称/节点名称搜索、节点筛选、状态筛选和“全部标为已读”；回复摘要仅用于展示，不参与搜索。失败或已中止的任务提供“重新执行”；该操作基于原任务创建新 Run，并使用稳定幂等号避免双击或响应丢失造成重复执行。

会话名称搜索由 Control Plane 执行，使用 200ms 输入防抖、每页 50 条和不易受并发更新影响的游标分页。全局快速切换在空关键词下不发起会话查询；有关键词时最多请求 10 条会话结果，并跳过不需要的精确总数统计。浏览器不一次性下载全部会话，也不构建消息正文索引。

任务中心最多展示最近 200 条记录。已读通知保留 30 天，未读通知保留 90 天；清理通知只删除通知索引，不删除会话、消息或任务记录。

### 9.3 审批边界

全局任务中心只提示“任务等待你的操作”，不承担独立审批管理。点击后回到对话中的必要操作卡片。操作卡片只展示做出安全决定所需的最小信息，不展示原始 JSON 或命令输出。

## 10. 关键交互状态

- 节点离线：历史会话可读，输入区禁用；未发送草稿保留。
- 网络断开：顶部出现非阻塞离线条；已提交请求保持幂等重试。
- 任务恢复中：显示“正在恢复任务状态”，不立即标记失败。
- 附件上传中：发送按钮禁用，文字显示剩余上传数量。
- 模型目录尚未加载：使用 Agent 默认值，选择器显示加载状态。
- 会话删除中：列表项进入不可重复点击状态；失败后恢复。

## 11. 实施顺序

实施必须以 `docs/reliability-design.md` 的协议和数据模型为基础：

1. 协议 v4、消息聚合、简洁进度和动态工作空间模型。
2. 浏览器事件游标、任务恢复和状态协调。
3. 折叠节点选择与折叠会话新建快捷键。
4. 设置页面与默认模型。
5. 全局任务中心。
6. 会话搜索、重命名、置顶和筛选。
7. 附件上传、粘贴图片和跨节点传输。

每一阶段需包含数据库迁移、API、UI、单元测试、断线测试和移动端浏览器测试。

## 12. 已确认的产品决定

1. 默认模型采用全局偏好；当前节点不支持时自动回退到 Agent 默认模型。
2. 仅当用户不在对应会话时，完成、失败和等待操作才形成未读通知；进入会话后自动已读。已读通知保留 30 天，未读通知保留 90 天。
3. 附件默认限制为单文件 20MB、单条消息最多 10 个、Control Plane 临时保留 7 天。
4. 对话内等待审批时展示一行必要的命令摘要和风险说明，不展示命令输出与原始数据。
5. 点击折叠状态的其他节点标识后，选择该节点并进入新会话草稿；点击当前节点只返回并保留原会话。
6. 当前操作按钮命名为“中止本轮”；在具备真实断点恢复能力前不提供“暂停 / 继续”。
7. Agent 启动目录是不可由 Web 修改的默认工作空间；Web 路径不设置额外根目录白名单，以 Agent 操作系统用户权限为边界。
8. 工作空间路径迁移必须明确确认；已绑定会话的工作空间只允许停用，不允许删除。
9. Agent 从不同目录重启时，新目录成为默认，旧会话仍绑定并可继续使用其原工作空间。
10. `--yolo` 只能由 Agent 本机启动参数开启；Web 必须在展开、折叠和节点接入列表中明确展示全权限状态，不能远程切换。
11. `--codex-proxy-only` 只影响 Agent 自身的出站路由，不修改或持久化代理环境；注册 CLI 必须独立传入同一参数。

## 13. v1 实施状态

已落地协议 v4、动态工作空间、产品级消息快照、简洁进度、断线重放与资源级刷新、节点与会话折叠、全局快速切换、全局默认模型、保留侧边栏的任务中心、任务搜索与重试、会话管理、消息分页、长对话虚拟渲染和附件上传。通知遵循“对应会话不可见才产生未读”的规则；高频会话切换使用选择身份与请求版本双重校验，后台响应不得抢占当前会话。

真正的断点暂停不在 v1 范围内；当前“中止本轮”会停止正在执行的 Turn，已经产生的副作用不会自动撤销。完整的故障注入验收仍以 `docs/reliability-design.md` 为准。
