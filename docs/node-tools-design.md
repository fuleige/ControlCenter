# 节点终端与文件管理设计

> 状态：终端、HTTPS 中转及 WebRTC 直连上传/下载已实现，新增会话 Fast 和估算输出速度。Controller Center 为 v0.3.16，Agent 为 v0.3.22，提供 Linux x64/glibc 和 macOS ARM64 包；2026-10-26 用户反馈两个平台实测未发现异常。当前验收范围见第 10.19 节，历史生产发布与验证记录保留在第 10 节，节点 Agent 升级独立安排。
> 日期：2026-10-08
> 范围：Controller Center Web、Control Plane、Linux/macOS Agent

## 1. 目标与边界

在已登录的 Web 界面中，为在线节点提供真正的交互式 Shell，以及文件浏览、上传和下载。以桌面 Chrome 为验收环境，其他浏览器和移动端在缺少直连下载所需能力时使用中转，不增加专门的直连兼容代码。Agent 保持主动连接 Control Plane，节点不开放固定的 HTTP 文件服务端口。

新增范围包含直连上传与下载，使用共用 WebRTC DataChannel 建立浏览器与 Agent 的直接数据通道，Control Plane 继续负责身份、任务、信令、进度与取消。每次打开文件管理页都后台检测能力并尝试实际建连；上传与下载分别检测所需浏览器能力，可用时各自默认直连，否则默认中转，用户可独立选择两种方式。已选择直连的任务失败后必须由用户确认改用中转，禁止自动切换。第一版可配置 STUN 辅助建连，不引入 TURN，不提供节点之间互传或跨传输方式的无缝续传。

终端是临时会话：同一节点允许同时打开多个，每次打开都创建独立的 PTY 和 Shell。界面不提供终端历史、重连、恢复或接管入口。文件管理只提供浏览、上传、下载；创建目录、重命名、删除和编辑交给 Shell。

上传与下载的单文件上限为 **1 GiB（1,073,741,824 字节，约 1 GB）**，直连不提高该上限。中转保留 Control Plane 完整暂存后交给下一端的流程；直连任务不分配 Control Plane 文件暂存空间。两种方式都使用有界分片和流式校验，内存占用不随文件大小增长。多文件批次逐项应用单文件上限，中转总暂存空间另受配额约束。

节点文件路径不受工作空间根目录限制，但所有读写都受 Agent **进程的操作系统用户权限**限制。Web 管理员登录身份不映射成节点系统用户，服务端不自动通过 `su`、`sudo` 或 SSH 提权或切换用户；用户在 Shell 中正常输入命令的行为不做专门过滤。终端与节点文件管理不套用 Codex 的审批/工作空间沙箱，`--safe` / `--yolo` 仍只决定 Codex 行为，界面以 Agent 系统用户说明这些节点工具的权限。

本功能与对话附件、对话内文件预览是三种不同用途：对话附件进入 Codex 输入缓存；对话内预览有 8 MiB 上限和查看历史；本设计的文件管理面向节点文件系统中的普通文件，必须另建传输生命周期和存储配额，不沿用附件的 20 MiB 限制。

## 2. 当前实现与新增约束

- Agent 通过 `/agent/connect` 建立经过节点凭证认证的 WSS；文件页独立 WebSocket 维护页面租约并接收直连信令。
- 协议 v5 增加可选 `node_files_direct_v1`，包含直连上传和下载；Agent v0.3.17 起在原生库加载成功后声明。当前安装包为 v0.3.22；只有 `node_files_v1` 的 Agent 继续使用中转，不禁止文件入口。
- `apps/control-plane/src/node-tools.ts` 根据任务传输方式分配暂存；直连只登记任务状态，不打开暂存文件、不预留文件配额。复用 `packages/node-files` 的路径、分片、哈希及文件身份校验。
- 节点文件当前按 1 MiB HTTP 分片传输、流式校验；不能复用对话预览中的 JSON/Base64 或整文件读取。DataChannel 帧大小与应用分片分别约束，见第 6.2 节。
- 现有 Nginx 的 `client_max_body_size 3m` 适配中转分片；保留 WebSocket Upgrade、缓冲、超时与响应范围配置。WebRTC 数据不经 Nginx HTTP 路由，STUN 与 UDP 网络条件需单独验证，既有 HTTP/WSS 代理配置不等于 WebRTC 代理支持。
- Agent 安装包使用 `npm install --ignore-scripts`，按构建目标携带 PTY 与 WebRTC 原生文件，使用 Node.js 24 构建基线，运行支持 Node 24 及以上并实际检测原生能力。Linux x64/glibc、macOS ARM64 验证记录分别保留；依赖加载失败只停用对应能力，不影响中转或聊天。

## 3. 界面与使用流程

### 3.1 终端

节点操作中提供“新开终端”；仅在侧边栏展开且选中节点时显示工具入口，侧边栏折叠时隐藏“新开终端”和“节点文件”。每次打开独立浏览器标签页：同一节点可打开多个标签页，每个标签页只有一个新终端。标签页只保存本次连接所需的内存状态，不把终端 ID、输入或输出写入浏览器存储。刷新页面结束旧终端并创建新终端；再次访问节点也只可新开。

终端页仅保留一行紧凑工具栏，显示节点名称、Agent 系统用户、连接状态、全屏和关闭按钮；启动目录与生命周期说明收进信息菜单，剩余可视高度交给终端。全屏使用 Chrome Fullscreen API，进入、退出或窗口尺寸改变时重新适配 PTY 尺寸。Shell 后续 `cd` 的实际目录以提示符为准。信息菜单说明关闭、刷新或断线后不能接回；正在运行的命令可能中断，Vim 等程序中的未保存内容可能丢失。点击界面内的关闭按钮可立即结束，不依赖浏览器关闭/刷新时一定弹出提示。终端内可正常使用方向键、Tab、Ctrl+C、复制粘贴、窗口尺寸变化，以及节点上已经安装的 Vim、less、top、tmux 等程序；不对 tmux 做特殊适配或会话管理。

点击“关闭终端”后不自动关闭浏览器标签页，保留本次已显示的输出；立即禁用输入、停止闪烁并隐藏输入光标，显示已结束提示，关闭按钮切换为“新开终端”。自然退出或连接结束采用相同的只读状态，用户可选中复制已有输出、手动关闭标签页，或开始新终端；不把这些输出写成可查询的历史终端。终端标签页留在后台时，只要连接健康就继续运行，不因暂时没有键盘输入而超时。

### 3.2 文件管理

节点操作中提供“节点文件”，与聊天中的会话文件历史入口区分。默认从 Agent 的默认工作空间目录开始，可输入绝对路径跳转到任何 Agent 用户可访问的目录；返回上级、进入子目录、刷新、查看名称/类型/大小/修改时间。文件列表分页或做有界读取，超大目录不得一次性推送到浏览器。软链接可标明类型；进入链接时由 Agent 解析真实路径并重新检查权限与文件类型。特殊文件、设备、管道和 Socket 不能作为普通文件上传/下载目标。

文件管理使用独立浏览器标签页，固定绑定打开时的节点；原聊天页切换节点不会改变该文件页的目标，也不会取消它的传输。在文件页内切换目录只是浏览操作，不取消已经开始的任务；任务的目标目录在创建时固定。关闭、刷新或离开整个文件页才应用本页任务的取消规则。

桌面文件页使用左右双栏：左侧目录浏览，路径栏、上传和下载操作集中在文件列表上方；右侧连接诊断与传输面板各自滚动。诊断展开或失败不改变左侧列表的高度；页面使用明确的可视高度约束，不将传输区放到被全局 `body overflow:hidden` 截断的位置。文件操作采用紧凑工具栏，桌面将文件数量、上传、下载和各自的方式选择放在一行，保持文件列表的可视空间。直连和中转作为常驻单选项显示，遵循第 3.3 节的默认值与手动选择规则。选中方式使用单选标记、蓝色边框和背景；直连显示“可用 / 检测中 / 不可用”，不可选时使用虚线边框并禁用选项，其简短原因显示在操作下方。常规传输说明与操作提示通过悬停提示和无障碍描述提供，避免重复占据多行。上传、下载按钮可操作时均使用蓝色；下载在没有选择文件时显示灰色，选择后显示数量。上传与下载分别检查能力，下载因浏览器保存 API 不可用时仍允许直连上传。详细连接错误继续保留在诊断区。窄屏将两组操作排为两行小按钮，保留操作入口与可滚动文件列表，不产生页面横向溢出。

已加载的条目按目录优先、名称自然排序显示，不改变服务端分页顺序。点击文件名称或文件行空白处切换选择，点击目录进入；全选只作用于当前已加载的普通文件及指向普通文件的软链接。刷新保留已加载分页中的有效选择，以及尚未提交的路径输入。上传成功后自动刷新当前目标目录；若用户已切换目录，不将其拉回上传位置。

每项传输显示实际方式、当前阶段、已确认字节、百分比、速度和用时，可展开任务编号与节点路径。直连下载显示接收到本机并写入的进度；中转原生下载显示准备进度，最终进度由浏览器下载列表管理。长时间无新进度时提示等待与取消入口。“清理已结束”只移除已完成、失败或取消的记录，保留活动任务；中转准备完成或已请求浏览器下载不等于本地保存完成，不能据此清理记录或宣称成功。

用户可以选取一个或多个本地**文件**上传到当前目录，或选取一个或多个节点普通文件下载。批量任务逐项展示进度与结果；单个文件失败不把其余成功文件误标为失败。上传目录必须已经存在，不自动创建目录。下载方式选择、批量保存与完成语义统一见第 3.3、6.3 节。

文件界面显示“单文件最大 1 GiB”。上传选择文件时立即检查大小；下载开始前由 Agent 检查源文件大小。超过 1 GiB 的文件显示“文件超过单文件大小限制”，不启动字节传输；同批符合限制的文件仍可继续。Control Plane 与 Agent 独立执行相同大小限制，不能只依赖前端检查。

上传开始前由 Agent 预检目录存在、可写及目标类型，再预检整批目标路径，列出同名冲突，由用户一次确认是否覆盖；没有冲突时直接开始，不逐个弹窗。取消确认时不启动该批上传，未确认时不能静默覆盖。上传提交前重新检查目标状态，发现目标在确认后发生变化时拒绝该项并提示重新操作。同一批或其他活动上传命中相同规范目标路径时也应拒绝冲突，避免两个任务互相覆盖。对本应用的上传使用目标路径互斥；这不能锁住 Shell、Codex 或其他程序的文件修改，覆盖确认提示需说明同时编辑的影响。

文件管理页关闭、刷新或离开后，结束其未完成的传输、关闭直连并清理临时内容；已提交的节点或本地文件不回滚。界面内“返回控制中心”在存在未完成或尚未确认完成的任务时先确认；中转原生下载提醒先查看浏览器下载列表。覆盖、改用中转和离开确认使用原生模态窗口，默认聚焦取消或继续传输，支持 Escape 取消和键盘焦点约束；不依赖浏览器关闭/刷新时一定弹出提示。同一页面仍打开时允许同一传输方式内的有界重试与 offset 续传，不提供关闭页面后的任务历史或续传入口。具体租约与失联处理见第 6.4 节。

### 3.3 打开页面后的协商与传输选择

每个文件页独立检查 Agent capability、安全上下文及 WebRTC、本浏览器到该 Agent 的实际连接。下载额外检查单文件保存 API 或批量目录 API；上传使用普通 File 对象，缺少保存 API 不禁用直连上传。节点声明支持不等于当前网络可达。只有 DataChannel 已打开、授权握手与小消息往返成功，才显示“直连可用”。探测只交换有界消息，不读文件、不创建文件传输任务、不弹出保存选择，也不阻塞目录浏览与中转入口。DataChannel 建连等待上限 8 秒，其他控制请求有独立超时；失败后提供“重新检测”，不无限重试。

| 检测状态 | 默认下载方式 | 直连选项 |
| --- | --- | --- |
| 正在检测 | 中转下载 | 暂不可选，显示“检测中” |
| 实际直连成功，浏览器支持保存 | 直连下载 | 可选 |
| Agent 支持，但当前网络建连失败 | 中转下载 | 暂不可选，显示原因与重新检测入口 |
| Agent 未声明直连能力或浏览器缺少所需能力 | 中转下载 | 不可选，说明具体原因 |
| 节点离线 | 不启动新下载 | 两种方式均不可用 |

下载操作提供“直连下载 / 中转下载”选择，并明确展示当前选择。仅在用户尚未手动选择且尚未启动操作时，根据检测结果更新默认值；用户手动选择中转后，探测成功也不改回直连。点击开始时固定本次单文件或整批的传输方式，后续探测结果不改变已开始、已排队任务的选择。

上传提供独立的“直连上传 / 中转上传”选择，采用相同的默认值和固定批次规则。两种上传方式复用整批节点覆盖预检、临时文件、文件身份复核、权限保留及原子重命名；区别在文件字节经过 DataChannel 直接写节点，还是先完整暂存到中心。

成功的连接由当前页面复用，不在探测后立即关闭。网络变化、连接失效或 Agent 连接世代变化时清除旧可用状态，停止接受旧协商结果，重新检查当前页面；协商设并发、消息量、频率和超时上限。页面关闭时释放连接，多个文件页不互相接管任务。检测失败后的默认中转与“已选直连任务失败后改用中转”分别处理：后者必须经过用户确认，见第 6.2 节。

## 4. 连接与协议

### 4.1 终端控制流

```text
浏览器终端页 --单终端 WebSocket--> Control Plane --现有 Agent WSS--> Agent
                   输入/输出/尺寸/关闭                 PTY + Shell
```

浏览器每开一个终端建立一个独立 WebSocket。Control Plane 在升级前校验管理员会话、明确受信任的浏览器 Origin、节点在线状态和 `terminal_pty_v1` capability；不能把 WebSocket 当成自动受 CORS 保护的请求。会话过期、注销或管理员 Token 轮换后也要关闭已建立的终端连接。每条浏览器连接只能拥有一个新建的终端。终端 ID 为临时随机 ID，只用于本次路由和清理，不写入 SQLite、URL、SSE 事件或历史列表。Control Plane 不允许客户端指定其他人的终端 ID，也不提供按 ID 重新连接的 API。

在现有 Agent WSS 上增加有界的临时消息类型：打开、打开结果、输入、输出、尺寸、关闭、退出和租约续期。它们**不进入可靠命令表或 Agent Outbox**，重连时不重放，避免重复启动 Shell。`open` 对同一个终端 ID 幂等；`close` 对重复/迟到请求幂等。消息携带节点连接世代和终端 ID，Control Plane 只接受当前连接的 Agent 输出，防止旧连接的迟到数据串到新终端。

PTY 输出按小帧转发并做背压：Agent 与 Control Plane 都限制待发送字节；浏览器在 xterm.js 完成消费输出后确认已消费字节，防止网络发送很快但终端解析队列无限积压。超过阈值先暂停 PTY 读取或传播背压，持续无法排空时结束该终端并明确显示原因。控制消息和终端输出都设大小、频率和尺寸边界，不能让持续输出无限占用内存。终端输出不落数据库或日志；日志只记录节点、临时终端 ID、开启/结束时间与错误类别，不记录输入命令、环境变量或屏幕内容。

### 4.2 文件控制流与数据流

列目录、预检、创建任务、查询进度、取消及直连信令仍走已认证的浏览器 API、文件页 WebSocket 和现有 Agent WSS；**文件字节不走现有 JSON WebSocket，也不走 Base64 预览接口**。中转时 Agent 向 Control Plane 发起出站 HTTPS 请求，沿用现有代理策略；短时任务令牌限定任务与方向，放在 Authorization 头，不放 URL。

```text
中转上传：浏览器 --分片--> Control Plane 暂存 --Agent 主动拉取--> 节点临时文件 --校验/提交--> 目标文件
中转下载：Agent --分片--> Control Plane 暂存 --HTTP Range--> 浏览器原生下载或网页保存
直连上传：浏览器 --WebRTC DataChannel--> 节点临时文件 --校验/提交--> 目标文件
直连下载：Agent --WebRTC DataChannel--> 浏览器流式校验与写入 --提交--> 用户选定文件
```

上传与下载都有独立任务 ID、所属页面/管理员会话、节点、连接世代、方向、规范路径、文件身份、大小、阶段、已确认 offset、状态、SHA-256 和租约。任务记录传输方式（`direct` / `relay`），当前页内存保存协商实例与本地文件句柄。一个任务使用一种传输方式，改用中转或从头重试创建新任务 ID，不能复用旧任务的 finalize 或 offset。SQLite 只保存当前任务和清理所需元数据，不形成用户可查询的历史。

任务阶段区分等待连接、传输、同方式重连续传、校验、提交、中转准备完成、失败与取消；最终失败后当前页面可以展示操作选择，但它不是继续占用传输资源的运行中任务。各段进度独立记录。上传只有收到 Agent 校验与最终提交确认后才显示成功；网页保存只有校验和写入提交成功后才显示已保存；原生下载不从准备完成或 HTTP 响应结束推断本地写盘成功。

状态迁移必须幂等；重复分片只能在 offset 和内容一致时被接受，错位分片返回服务端真实 offset。本期 Control Plane 或 Agent 重启后，不自动恢复旧文件任务，而是将未完成任务明确标为中断并清理，不能把半个文件标为成功。业务控制消息不进入现有 Codex 命令重放队列；当前页存活期间按任务 ID 查询并重试，进程重启后不重放文件写入。任何失败都保留明确错误类别供界面展示。

只有中转任务在 Control Plane 专用目录分配内容暂存，权限 `0700/0600`，与对话附件隔离；按声明大小预留总配额并检查磁盘余量。直连任务不预留服务端文件空间、不创建 `.part`，但仍受单文件上限、节点并发和全局任务数限制。接收方检查实际累计字节与声明大小，超限立即停止。服务端启动时清理失效元数据与中转临时文件；任何完成、失败、取消和超时都有清理路径。清理失败的内容继续计入占用并重试，不能先删除追踪记录。文件校验使用流式哈希，1 GiB 文件也不能整个读进 Node 或浏览器内存。

Agent 的上传临时文件位于任意目标目录，不能仅清理自己的缓存目录。Agent 为这些临时文件保存最小清理登记，包含任务 ID、规范临时路径及文件身份；启动时清理中断任务的登记文件，不扫描整个文件系统，也不恢复旧传输。登记与创建、提交、取消的顺序需覆盖进程崩溃场景，删除前核对仍是本任务的临时文件，已重命名到目标的文件不能被旧登记误删。

### 4.3 直连授权与信令

Control Plane 对协商校验管理员会话、Origin、页面归属、节点在线状态及直连 capability。信令绑定页面 ID、节点 ID、当前 Agent 连接世代与一次协商 ID；SDP、ICE candidate 和 DataChannel 握手设大小、频率、数量及超时上限。旧世代、已结束页面和迟到协商消息直接拒绝，不进入可靠命令表或 Agent Outbox。

页面建连授权只允许握手与探测，不授予文件读写权限。每个文件任务另由 Control Plane 授权，绑定节点、页面、任务 ID、方向、规范路径、文件身份、大小及所协商的对端。使用短时任务凭证并绑定该连接的 DTLS 指纹或等价对端证明；Agent 根据中心下发的任务元数据操作文件，不能接受仅凭任务 ID 或客户端自报路径的请求。Cookie、管理员 Token 和节点长期凭证不转发到对端，令牌和完整信令不写访问日志。

数据通道即使保持连通，也必须服从 Control Plane 的页面、会话与任务租约。注销、撤销节点、租约过期或控制连接世代失效后停止读写；Agent 的本地租约检查保证中心取消消息丢失时也能停止。连接成功不等于任务授权成功，不因直连绕过文件预检、路径互斥或大小限制。

## 5. 终端生命周期

1. WebSocket 验证通过后，Control Plane 分配终端 ID 并请求 Agent 打开。Agent 使用 PTY 启动交互式 Shell，用户名、环境变量和权限继承 Agent 进程，初始目录为 Agent 默认工作空间；优先使用有效的 `$SHELL`，macOS 回退 `/bin/zsh`，Linux 优先回退 `/bin/bash`，不可用时回退 `/bin/sh`。设置匹配浏览器终端的 `TERM`，传入有效的初始行列尺寸；不通过命令字符串拼接启动。Agent 确认成功后页面才显示“已连接”。启动失败显示真实错误，不留空白终端。浏览器在等待启动时关闭，也必须取消迟到的 PTY 启动结果。
2. 浏览器将键盘输入写入 PTY；Agent 将 PTY 输出转给浏览器的 xterm.js；浏览器尺寸变化调用 PTY resize。Vim/tmux 的当前画面由仍然运行的程序绘制。没有恢复功能，因此不需要服务端终端屏幕快照或持久化滚屏。
3. 用户点击“关闭终端”、Shell `exit`、终端进程退出，或浏览器 WebSocket 正常断开时立即开始清理。页面关闭事件只作为尽力而为的快速通知，不是唯一清理依据。
4. 浏览器异常退出/网络静默断开由 Control Plane 主动 ping/pong 判定；收到有效 pong 后才为该终端向 Agent 续租，不能仅因服务端还在发送 ping 就续租。建议 15 秒检测，终端租约 60 秒；无有效续租后 Agent 本地终止 PTY。Control Plane 进程崩溃、Agent 到中心链路中断、Agent 重启时同样不会留下可恢复的终端。
5. 终止过程关闭 PTY、通知其管理的 Shell/前台程序，给短暂退出时间，再回收仍受其管理的进程与资源；清理必须幂等，不能按程序名误杀节点其他任务。tmux、nohup 等明确脱离终端的后台程序可独立存在，按正常终端语义处理，不承诺关闭网页即删除这些后台会话或任务。

这里的心跳只判断“浏览器是否仍连接”，**不是命令空闲超时**。网络闪断一旦造成连接断开，旧终端会结束，页面也不能重新接回；这是取消恢复功能后的明确取舍。

## 6. 文件传输细节

### 6.1 浏览与路径

Control Plane 固定节点身份，不接受浏览器冒用其他节点的路径上下文。Agent 负责解析路径、列目录、检查权限与文件类型；路径可以越出工作空间，目录软链接可指向其他可访问路径。列表结果只返回文件元数据，不读取文件正文；显示隐藏文件，浏览/下载只要求对应读取权限，不能复用工作空间验证中的“必须可读写”条件。普通文件操作开始时重新检查路径和文件描述符，避免用户浏览后文件已变化却继续使用旧结果。

下载只读取有限大小的普通文件，打开后确认文件描述符的类型、大小和身份，并在传输前后核对文件描述符及原路径的身份、大小、修改时间等变化；发现变化就失败。直连或网页保存必须等源文件检查及最终 SHA-256 成功后再提交本地写入流，不能把已收到全部字节标为成功。该检查不等于文件系统快照，不提供边写边下载的强一致快照。上传在已解析的目标目录创建不可预测名称的临时文件，核对字节数与 SHA-256 后提交；临时文件与目标位于同一文件系统，最终文件以原子重命名方式出现，失败时清理临时文件。上传不能覆盖目录、特殊文件或最终路径上的软链接；需要写链接指向的普通文件时，先进入真实目录再上传。

临时文件使用 `0600`；新文件提交时应用 Agent 用户的正常 umask，覆盖现有文件时保留其基本 Unix 权限与归属，无法保留时明确失败，避免上传一个文件后意外改变原有权限。上传不承诺保留浏览器文件的可执行位、ACL、扩展属性或修改时间，此类操作交给 Shell。存在目标文件时遵循用户已确认的冲突规则，不能无提示覆盖。上传与下载都不需要 Shell 解析路径，路径作为数据传递，避免命令拼接问题。

### 6.2 分片、同方式续传与失败选择

续传只覆盖**同一页面仍打开、同一任务和租约仍有效**的网络闪断，不能跨进程重启或跨直连/中转续传。浏览器上传继续用 `File.slice()`；中转各段查询其接收方确认的 offset，直连重新握手后查询当前任务的接收确认位置。只允许从已完整写入并校验的分片边界继续，验证同一节点、路径与文件身份；源文件变化就失败。网络错误使用有次数与时间上限的退避重试，进展超时不因重试消息而无限延后。

HTTP 分片维持 1 MiB。直连可沿用逻辑分片及哈希语义，但每个分片拆为小 DataChannel 帧，初始帧上限建议 16 KiB，并满足双方协商的 `maxMessageSize`（含帧头）。使用可靠、有序 DataChannel，同时限制 `bufferedAmount`、在途分片和接收写盘队列；发送缓冲排空不等于接收方已经写入。接收方完整校验并写入分片后才 ACK；确认丢失先查询真实 offset，重复分片核对内容，错位返回接收方实际位置。同一任务的写入与 finalize 串行处理。

中转保持浏览器/Agent、Control Plane 的分片与整体 SHA-256 校验；直连下载由 Agent 流式计算源文件 SHA-256、浏览器流式计算接收内容 SHA-256。收到长度、源文件最终检查与整体哈希全部通过才提交。续传时可重新流式读取或接收已有前缀以重建哈希，不要求序列化哈希内部状态；接收位置不能由发送端猜测。临时文件长度与记录不一致时明确失败或核对修正，不能跳过缺失字节。

直连上传每个逻辑分片由 Agent 校验、写入并同步后确认；断线重握手查询节点确认 offset，重复分片核对已写内容。浏览器从 File 有界读取重建整体哈希，Agent 对临时文件做整体哈希并复核目标后提交。直连下载重连保留当前未提交写入流和哈希状态，仅对最后一个完全相同分片返回重复确认，不重复写入或累加哈希。每项最多 2 次同方式重连，发送确认及 Agent 重连等待上限各 30 秒、节点等待接收分片上限 45 秒，始终受 60 秒页面/任务租约约束。失败后的新任务要等待 Agent 的 `files.stopped` 确认已释放旧文件资源。

直连最终建连失败或同方式重连续传耗尽后，在当前页面提供“重试直连 / 改用中转 / 取消”。**只有用户点击“改用中转”才允许创建中转任务、分配服务端暂存或开始中转传输**，不能仅因后台检测失败、超时或取消弹窗而自动降级。已传过字节时明确提示“将从头重新传输”，不拼接两种方式的内容。重试或改用中转前重新检查源/目标文件、有效租约及覆盖授权，并等待旧任务停止、未提交内容清理和路径互斥释放。复用已授权的本地保存句柄，但不复用旧写入流、任务凭证或 finalize。

上述选择只处理可重试的连接问题。用户取消保存窗口、拒绝权限、文件权限不足、文件变化、空间不足或校验失败分别报告原因，不自动中转，也不把换路线当作解决业务错误的方式。失败后的选择只属于当前页和该项任务，不因一项确认而改掉整批其他文件的路线。

取消后的迟到分片或 finalize 必须拒绝，Agent 上的最终提交与取消串行处理。取消到达时文件若已提交，保留结果并报告已完成，不能回滚或删除目标；若断线导致无法判断提交是否完成，显示“提交结果不确定，请检查目标文件”，不能声称“取消后没有写入”。这是原子写入的确认可能丢失时的明确边界。

### 6.3 下载保存与完成语义

| 用户操作 | 内容来源 | 保存与进度 |
| --- | --- | --- |
| 直连下载 | Agent DataChannel | 网页流式校验与写入用户选定文件，成功关闭写入流后显示已保存 |
| 开始时选择中转下载 | Control Plane 完整暂存后的 HTTP 响应 | 沿用 Chrome 原生下载栏；网页只报告准备与请求下载 |
| 直连失败后确认改用中转 | 新中转任务完整暂存后的 HTTP 响应 | 网页从头流式写入此前选定文件，保持同一保存位置与网页进度 |

直连下载要求安全上下文及所需 File System Access API。单文件点击下载时先调用 `showSaveFilePicker()` 取得文件句柄，再检查或恢复连接并创建任务；不能先等待异步协商才请求保存选择。取消选择直接结束操作，不启动中转。浏览器没有保存能力时默认中转；没有文件系统保存 API 不等于节点不支持 WebRTC。

多个文件直连下载默认一次调用 `showDirectoryPicker()` 选择保存目录，在该次用户操作中一并取得写权限，随后逐项排队、校验及提交。本地同名文件在写入前整批确认，未确认不覆盖；写入前复核已有文件基本状态，变化时拒绝该项，中途重试不能绕过同名规则。保存目录授权或写入被拒绝时明确失败，不反复自动弹窗。确认改用中转的文件复用对应本地句柄，其他批次项维持原选择。页面只保留本次内存中的句柄，不持久化或在新页接管。

网页保存使用有界流，不汇总成整文件 Blob。全部字节写入待提交流后，仍需核对长度、源文件最终检查和 SHA-256，随后等待 `close()` 成功才显示“已保存”。失败或取消中止未提交写入流，不删除用户选定目标或已提交文件；保存对话框可能已创建的空文件也不能当作任务临时文件随意删除。

中转快照的 HTTP 端点保留 `Range`、`If-Range`、`Content-Range`、`Content-Length`、`ETag`、`Content-Disposition` 及正确的 206/416，不自动压缩改变字节表示。网页保存复用该端点与范围能力；原生下载由浏览器管理保存和可能的续传，不保证 Chrome 必定自动续传。Range 只在任务与页面有效期内提供。准备进度达到 100% 只表示中心暂存校验通过；“已请求浏览器下载”及 HTTP 响应结束均不代表用户磁盘保存成功。浏览器阻止多文件下载时提示允许或逐项点击，不误标为已保存。

准备完成但未请求下载的文件设有有限保留窗口，建议 30 分钟；过期后显示“准备文件已过期，请重新下载”。正在发送或重试的健康传输不因这个等待窗口到期而被删；下载响应结束后可以短时保留同一任务的快照供浏览器重试，但仍受页面租约、总配额与清理期限约束。任务结束且临时文件清理成功后删除清理用元数据，不积累历史文件任务。

### 6.4 页面关闭与失联清理

文件管理页使用一个轻量控制连接维护本页活动任务的租约；页面实例 ID 只存在当前页面内存中，刷新后生成新 ID，不能用新页面接管旧任务。页面关闭/离开的通知用于快速取消，后台租约超时作为兜底，不能只依赖页面退出回调。

文件控制连接允许同一页面在短暂断网后、租约过期前重新连接；这是当前任务的重试，与终端不允许重新接入的规则分别处理。建议页面租约为 60 秒，重试不延长没有有效心跳的租约；页面在后台但连接健康时可继续。到期后 Control Plane 停止任务、关闭仍在发送的下载响应、撤销任务令牌，并通知 Agent 取消。Agent 也保留任务超时和失联清理，防止控制面的取消通知未送达。清理允许幂等重试，取消后不提供继续入口。

管理员会话过期、注销或撤销也停止其活动文件任务与页面直连。短时任务凭证可在任务与页面仍有效时续期，过期不能迫使正常的慢速 1 GiB 传输从头开始；已取消任务不能换取新凭证。传输进展超时与页面失联超时分别处理，校验和本地提交阶段继续维持页面/任务租约。后台网络复测成功不能复活已结束任务。

关闭/刷新页、租约过期及进程重启时，关闭 DataChannel 与文件描述符，中止网页未提交的写入流，清理服务端和 Agent 的任务临时文件；已提交文件保留。原生下载仍取消尚未发送完的 HTTP 响应，但已交付字节与本地文件由 Chrome 管理，应用不能撤回。清理不能删除用户保存目标或其他进程的文件；中心进程重启后不能凭仍存活的直连继续传输。

## 7. 权限、资源与兼容

- Shell 与文件都使用 Agent 的系统用户。管理员会话、Origin、节点与任务授权必须在 Control Plane 校验，Agent 独立校验路径、大小、文件身份与任务租约；直连不绕过上述限制。
- 日志只记录任务编号、节点、传输/保存方式、阶段、确认字节、错误类别及页面结束原因；不记录文件正文、终端输入输出、凭证或完整 SDP/ICE。中转内容只保留短时窗口，不能进入长期备份。
- 每节点默认 8 个 PTY、2 个活动文件任务；两种传输方式共享文件任务并发预算，页面内按批次排队。独立限制页面直连数与协商并发，连接探测不创建文件任务；达到连接上限时说明原因，不挤掉其他页面的健康连接。限制 CPU、内存、发送队列及写盘队列，不能影响 Agent 心跳或 Codex Run 调度。
- 中转默认总配额 8 GiB、磁盘保留余量 512 MiB，均可按部署容量配置；直连不消耗中心文件配额，但本地保存仍可能因磁盘空间不足失败。用户确认改用中转时重新执行配额检查，不能绕过限制。
- 终端继续使用 xterm.js 与 node-pty，中转复用 Fastify、Node 流、Range 和共享文件 I/O；不引入完整文件管理器、tus/Uppy 服务或自研 NAT 穿透协议。Agent 选用 `node-datachannel@0.33.4` 的平台预编译原生库，按运行平台安装，依赖加载失败只停用直连；项目验证边界见第 10 节。
- Web/Control Plane 控制入口维持 HTTPS/WSS。控制面 `NODE_FILES_STUN_URLS` 为逗号分隔的 STUN 地址，最多 8 个；未设置时使用 `stun:stun.cloudflare.com:3478`、`stun:global.stun.twilio.com:3478`、`stun:stun.l.google.com:19302` 三个候选，显式留空只交换主机候选。Cloudflare 列在首位作为首选测试服务；WebRTC 同时探测候选服务器并自行选择实际可用路径，列表顺序不保证串行访问或最终路径。多个地址提高覆盖机会，不保证 NAT 跨网可达，发布前仍需验证实际网络。直连需要节点与浏览器的 UDP 出站及相关回包，不要求固定公网 HTTP 监听或手动端口映射。现有 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 和 `--codex-proxy-only` 的 HTTP/WSS 含义保持不变，不能宣称它们自动代理 WebRTC。当前不配置 TURN；以后增加 TURN 时，使用 relay candidate 的路线必须标为中继，不能显示直连。
- 前端记录浏览器环境、协商、两端连接、通道授权和传输中断的失败阶段。文件页提供诊断详情，失败时展开，并在浏览器控制台输出有界诊断记录；展示各 STUN 地址、浏览器错误码/错误文本、两端候选类型数量、连接状态和检测过程，不输出原始 SDP、候选 IP/端口或令牌。`icecandidateerror` 的 701 表示浏览器报告此地址探测不可达；DNS、UDP、防火墙或部分接口路径仍需区分。成功公网候选优先于局部错误；已建立直连不因单个 STUN 错误降级。没有来源信息或没有返回结果时标为未单独确认，不把建连超时等同于 STUN 服务宕机。浏览器只能逐项观察自己的探测；当前 Agent 的候选信息不能证明其逐个 STUN 地址的访问结果。检测失败不启动文件任务，不自动切换已有任务到中转。
- PTY 及新增 WebRTC 原生依赖按实际 OS、架构、Linux libc 与 Node.js 24 目标打包，构建后验证实际独立安装包。Linux x64/glibc 和 macOS ARM64 是首批验证目标，Linux 结果不能代替 macOS；模块加载失败只停用对应 capability，不带崩聊天与中转。下载页继续明确系统目标、独立 Agent 版本与 SHA-256。
- 新协议消息通过可选 capability 守卫，保持协议 v5；旧 Agent 仍可中转。Controller Center 与 Agent 独立发布。Agent 运行代码或原生依赖变化时独立升级其版本，当前安装包为 v0.3.22；Linux x64/glibc 和 macOS ARM64 已获本轮用户实机反馈，产物哈希与验收范围见第 10.19 节，历史部署与节点升级边界见第 10 节。

直连新增验收按以下分组，原有中转通过不代表直连通过：

- 协商与选择：每次开页探测；能力支持但网络不可达；DataChannel 打开与授权往返；检测超时不阻塞目录；旧 Agent、浏览器 API 缺失、非安全上下文、节点离线；晚到结果不覆盖手动选择或已排队路线；连接数限制与多页隔离。
- 网络：同网段、不同 NAT、公网 IPv4/IPv6、移动网络、禁 UDP、HTTP 代理环境、STUN 不可达、网络切换和 Agent 重连；记录实测成功率与原因，不预设所有网络能直连。
- 保存：单文件点击触发选择、批量一次选目录、本地同名确认、取消/拒绝授权、源文件变化、校验失败、磁盘满、未提交写入流清理、最终 `close()` 失败、关闭页后的目标保护；1 GiB 完整性及有界内存。
- 重试与中转确认：同任务直连重连续传和 ACK 丢失；重试耗尽后先停止；未经点击“改用中转”不创建中转任务或暂存；确认后新任务从头开始、复用保存位置并重新检查配额；取消确认不传输；业务错误不换路线；旧任务迟到消息不能提交新任务。
- 生命周期与授权：注销、节点撤销、中心控制连接/进程失效、页面租约到期，即使 DataChannel 仍可通信也停止；跨页、跨节点、错误方向/路径、过期凭证、错误对端和旧连接世代请求拒绝；健康后台页面不按输入空闲结束。
