# 节点终端与文件管理设计

> 状态：已实现并完成 Linux/Chromium 验证，已完成本机部署与实际网页检查；macOS 待实际环境验收
> 日期：2026-10-01
> 范围：Controller Center Web、Control Plane、Linux/macOS Agent

## 1. 目标与边界

在已登录的 Web 界面中，为在线节点提供真正的交互式 Shell，以及文件浏览、上传和下载。本期以桌面 Chrome 为验收环境，其他浏览器和移动端不增加专门兼容代码。Agent 保持主动连接 Control Plane，节点不开放入站端口；本期所有文件字节经 Control Plane 中转，不做节点与浏览器直连或直连失败协商。任务模型与传输链路分开，以便未来评估直连，但本期不预埋直连协商界面。

终端是临时会话：同一节点允许同时打开多个，每次打开都创建独立的 PTY 和 Shell。界面不提供终端历史、重连、恢复或接管入口。文件管理只提供浏览、上传、下载；创建目录、重命名、删除和编辑交给 Shell。

本期上传与下载的单文件上限为 **1 GiB（1,073,741,824 字节，约 1 GB）**，以这一范围内的稳定传输为验收目标。保留 Control Plane 完整暂存后交给下一端的流程；文件仍按小分片传输和流式校验，内存占用不随文件大小增长。多文件批次逐项应用单文件上限，总暂存空间另受配额约束。

节点文件路径不受工作空间根目录限制，但所有读写都受 Agent **进程的操作系统用户权限**限制。Web 管理员登录身份不映射成节点系统用户，服务端不自动通过 `su`、`sudo` 或 SSH 提权或切换用户；用户在 Shell 中正常输入命令的行为不做专门过滤。终端与节点文件管理不套用 Codex 的审批/工作空间沙箱，`--safe` / `--yolo` 仍只决定 Codex 行为，界面以 Agent 系统用户说明这些节点工具的权限。

本功能与对话附件、对话内文件预览是三种不同用途：对话附件进入 Codex 输入缓存；对话内预览有 8 MiB 上限和查看历史；本设计的文件管理面向节点文件系统中的普通文件，必须另建传输生命周期和存储配额，不沿用附件的 20 MiB 限制。

## 2. 实施前现状与实现约束

- Agent 已通过 `/agent/connect` 向 Control Plane 建立经过节点凭证认证的 WebSocket；浏览器业务主要走已登录的 `/api/*` 与 SSE。Agent 未提供 PTY 或节点文件传输能力。
- `packages/protocol` 当前是协议 v5，`agent.hello` 已支持可选 capability。新消息只能发给声明对应 capability 的 Agent，旧 Agent 仍可在线，并在界面明确提示“需升级 Agent”。
- 现有附件上传已有创建任务、分片 offset、最终 SHA-256 校验的模式，可以复用**思路和部分基础设施**。现有浏览器整文件 `arrayBuffer()`、Control Plane `readFileSync()`、Agent `response.arrayBuffer()` 及 WebSocket JSON/Base64 文件预览路径都不能直接用于大文件。
- 现有 Nginx 默认 `client_max_body_size 3m`，只适合小分片；新增终端 WebSocket 路由需显式透传 Upgrade，传输路由需核对请求/响应缓冲、超时与体积限制。
- Agent 独立安装包目前使用 `npm install --ignore-scripts`。PTY 原生模块若需要编译或安装脚本，现有打包方式不能直接沿用；发布前必须分别在目标 Linux/macOS 架构上验证安装和运行。

## 3. 界面与使用流程

### 3.1 终端

节点操作中提供“新开终端”；仅在侧边栏展开且选中节点时显示工具入口，侧边栏折叠时隐藏“新开终端”和“节点文件”。每次打开独立浏览器标签页：同一节点可打开多个标签页，每个标签页只有一个新终端。标签页只保存本次连接所需的内存状态，不把终端 ID、输入或输出写入浏览器存储。刷新页面结束旧终端并创建新终端；再次访问节点也只可新开。

终端页仅保留一行紧凑工具栏，显示节点名称、Agent 系统用户、连接状态、全屏和关闭按钮；启动目录与生命周期说明收进信息菜单，剩余可视高度交给终端。全屏使用 Chrome Fullscreen API，进入、退出或窗口尺寸改变时重新适配 PTY 尺寸。Shell 后续 `cd` 的实际目录以提示符为准。信息菜单说明关闭、刷新或断线后不能接回；正在运行的命令可能中断，Vim 等程序中的未保存内容可能丢失。点击界面内的关闭按钮可立即结束，不依赖浏览器关闭/刷新时一定弹出提示。终端内可正常使用方向键、Tab、Ctrl+C、复制粘贴、窗口尺寸变化，以及节点上已经安装的 Vim、less、top、tmux 等程序；不对 tmux 做特殊适配或会话管理。

点击“关闭终端”后不自动关闭浏览器标签页，保留本次已显示的输出；立即禁用输入、停止闪烁并隐藏输入光标，显示已结束提示，关闭按钮切换为“新开终端”。自然退出或连接结束采用相同的只读状态，用户可选中复制已有输出、手动关闭标签页，或开始新终端；不把这些输出写成可查询的历史终端。终端标签页留在后台时，只要连接健康就继续运行，不因暂时没有键盘输入而超时。

### 3.2 文件管理

节点操作中提供“节点文件”，与聊天中的会话文件历史入口区分。默认从 Agent 的默认工作空间目录开始，可输入绝对路径跳转到任何 Agent 用户可访问的目录；返回上级、进入子目录、刷新、查看名称/类型/大小/修改时间。文件列表分页或做有界读取，超大目录不得一次性推送到浏览器。软链接可标明类型；进入链接时由 Agent 解析真实路径并重新检查权限与文件类型。特殊文件、设备、管道和 Socket 不能作为普通文件上传/下载目标。

文件管理使用独立浏览器标签页，固定绑定打开时的节点；原聊天页切换节点不会改变该文件页的目标，也不会取消它的传输。在文件页内切换目录只是浏览操作，不取消已经开始的任务；任务的目标目录在创建时固定。关闭、刷新或离开整个文件页才应用本页任务的取消规则。

桌面文件页使用左右双栏：左侧目录浏览，右侧始终可见的传输面板，各自滚动；页面使用明确的可视高度约束，不将传输区放到被全局 `body overflow:hidden` 截断的位置。创建下载任务后立即显示请求状态，准备阶段显示已确认字节、百分比、速度和用时。每项可展开任务编号、节点路径与阶段，编号用于定位服务端日志；长时间无新进度时提示等待与取消入口。最终下载仍由 Chrome 下载栏管理。

用户可以选取一个或多个本地**文件**上传到当前目录，或选取一个或多个节点普通文件下载。批量任务逐项展示进度与结果；单个文件失败不把其余成功文件误标为失败。上传目录必须已经存在，本期不自动创建目录。下载采用第 11 节的 Chrome 原生下载方案：网页显示节点到 Control Plane 的准备进度，准备好后请求 Chrome 下载；请求浏览器下载不等于浏览器已接受或写盘完成，最终状态以 Chrome 下载栏为准。多文件下载若被浏览器限制，提示用户允许多文件下载或逐项点击已准备文件的下载按钮，不把请求发送成功标成文件已保存。

文件界面显示“单文件最大 1 GB”。上传选择文件时立即检查大小；下载开始前由 Agent 检查源文件大小。超过 1 GiB 的文件显示“文件超过单文件大小限制”，不启动字节传输；同批符合限制的文件仍可继续。Control Plane 与 Agent 独立执行相同大小限制，不能只依赖前端检查。

上传开始前由 Agent 预检目录存在、可写及目标类型，再预检整批目标路径，列出同名冲突，由用户一次确认是否覆盖；没有冲突时直接开始，不逐个弹窗。取消确认时不启动该批上传，未确认时不能静默覆盖。上传提交前重新检查目标状态，发现目标在确认后发生变化时拒绝该项并提示重新操作。同一批或其他活动上传命中相同规范目标路径时也应拒绝冲突，避免两个任务互相覆盖。对本应用的上传使用目标路径互斥；这不能锁住 Shell、Codex 或其他程序的文件修改，覆盖确认提示需说明同时编辑的影响。

文件管理页关闭、刷新或离开后，结束其未完成的传输并清理两端临时文件；已经成功写入节点的文件不回滚。页面仍打开时允许网络闪断后的自动重试和 offset 续传，不提供关闭页面后的任务历史或续传入口。已经交给浏览器的下载，服务端仍会取消尚未发送完的响应；已经交付的字节及本地文件由浏览器管理，应用不能撤回。正常取消与异常失联后的清理都要有明确状态。

## 4. 连接与协议

### 4.1 终端控制流

```text
浏览器终端页 --单终端 WebSocket--> Control Plane --现有 Agent WSS--> Agent
                   输入/输出/尺寸/关闭                 PTY + Shell
```

浏览器每开一个终端建立一个独立 WebSocket。Control Plane 在升级前校验管理员会话、明确受信任的浏览器 Origin、节点在线状态和 `terminal_pty_v1` capability；不能把 WebSocket 当成自动受 CORS 保护的请求。会话过期、注销或管理员 Token 轮换后也要关闭已建立的终端连接。每条浏览器连接只能拥有一个新建的终端。终端 ID 为临时随机 ID，只用于本次路由和清理，不写入 SQLite、URL、SSE 事件或历史列表。Control Plane 不允许客户端指定其他人的终端 ID，也不提供按 ID 重新连接的 API。

在现有 Agent WSS 上增加有界的临时消息类型：打开、打开结果、输入、输出、尺寸、关闭、退出和租约续期。它们**不进入可靠命令表或 Agent Outbox**，重连时不重放，避免重复启动 Shell。`open` 对同一个终端 ID 幂等；`close` 对重复/迟到请求幂等。消息携带节点连接世代和终端 ID，Control Plane 只接受当前连接的 Agent 输出，防止旧连接的迟到数据串到新终端。

PTY 输出按小帧转发并做背压：Agent 与 Control Plane 都限制待发送字节；浏览器在 xterm.js 完成消费输出后确认已消费字节，防止网络发送很快但终端解析队列无限积压。超过阈值先暂停 PTY 读取或传播背压，持续无法排空时结束该终端并明确显示原因。控制消息和终端输出都设大小、频率和尺寸边界，不能让持续输出无限占用内存。终端输出不落数据库或日志；日志只记录节点、临时终端 ID、开启/结束时间与错误类别，不记录输入命令、环境变量或屏幕内容。

### 4.2 文件控制流与数据流

文件列目录、创建任务、查询进度、取消等控制消息仍走现有 Agent WSS 或已认证的浏览器 API；**文件字节不走现有 JSON WebSocket，也不走 Base64 预览接口**。Agent 只向 Control Plane 发起出站 HTTPS 请求，沿用现有 Agent 出站代理策略；使用短时、仅限本任务和方向的令牌，令牌放在 Authorization 头，不放 URL。

```text
上传：浏览器 --有界分片--> Control Plane 暂存 --Agent 主动拉取--> 目标目录临时文件 --校验/提交--> 目标文件
下载：Agent --有界分片--> Control Plane 暂存 --HTTP Range/浏览器下载--> 用户电脑
```

为上传与下载分别定义独立任务 ID、所属页面实例/管理员会话、节点 ID、方向、源/目标路径、大小、阶段、各段已确认 offset、状态、SHA-256、过期时间及临时文件名。任务元数据和 offset 保存在 Control Plane 的 SQLite 中，文件内容只在磁盘暂存；元数据服务于当前任务、重试和清理，不形成用户可查询的历史。任务状态至少包括 `created`、`transferring`、`verifying`、`ready`、`completed`、`failed`、`cancelled`。浏览器到控制面、控制面到 Agent 等不同阶段独立记录进度，不能用“浏览器已经上传完”代表“节点文件已写入”。上传只有收到 Agent 的校验与最终提交确认后才显示成功；下载区分“准备完成”“请求浏览器下载”和“服务端响应发送结束”，均不代表浏览器本地写盘完成。

状态迁移必须幂等；重复分片只能在 offset 和内容一致时被接受，错位分片返回服务端真实 offset。本期 Control Plane 或 Agent 重启后，不自动恢复旧文件任务，而是将未完成任务明确标为中断并清理，不能把半个文件标为成功。业务控制消息不进入现有 Codex 命令重放队列；当前页存活期间按任务 ID 查询并重试，进程重启后不重放文件写入。任何失败都保留明确错误类别供界面展示。

文件内容暂存于 Control Plane 专用目录，权限 `0700/0600`，与对话附件隔离；每任务按已声明大小预留容量，并执行 1 GiB 单文件上限、节点并发、服务端总空间和磁盘余量检查。接收过程中也检查累计实际字节数，超过声明大小或上限时停止接收并清理，避免绕过预检。服务端启动时能清理过期/失去元数据的临时文件；任何完成、失败、取消和超时都有清理路径。清理仅处理专用暂存目录以及 Agent 创建的临时文件，不能删除已提交的用户目标文件。清理失败的内容继续计入占用并重试清理，不因元数据提前删除而失去追踪。文件校验使用流式哈希，1 GiB 文件也不能整个读进 Node 或浏览器内存。

Agent 的上传临时文件位于任意目标目录，不能仅清理自己的缓存目录。Agent 为这些临时文件保存最小清理登记，包含任务 ID、规范临时路径及文件身份；启动时清理中断任务的登记文件，不扫描整个文件系统，也不恢复旧传输。登记与创建、提交、取消的顺序需覆盖进程崩溃场景，删除前核对仍是本任务的临时文件，已重命名到目标的文件不能被旧登记误删。

## 5. 终端生命周期

1. WebSocket 验证通过后，Control Plane 分配终端 ID 并请求 Agent 打开。Agent 使用 PTY 启动交互式 Shell，用户名、环境变量和权限继承 Agent 进程，初始目录为 Agent 默认工作空间；优先使用有效的 `$SHELL`，macOS 回退 `/bin/zsh`，Linux 优先回退 `/bin/bash`，不可用时回退 `/bin/sh`。设置匹配浏览器终端的 `TERM`，传入有效的初始行列尺寸；不通过命令字符串拼接启动。Agent 确认成功后页面才显示“已连接”。启动失败显示真实错误，不留空白终端。浏览器在等待启动时关闭，也必须取消迟到的 PTY 启动结果。
2. 浏览器将键盘输入写入 PTY；Agent 将 PTY 输出转给浏览器的 xterm.js；浏览器尺寸变化调用 PTY resize。Vim/tmux 的当前画面由仍然运行的程序绘制。没有恢复功能，因此不需要服务端终端屏幕快照或持久化滚屏。
3. 用户点击“关闭终端”、Shell `exit`、终端进程退出，或浏览器 WebSocket 正常断开时立即开始清理。页面关闭事件只作为尽力而为的快速通知，不是唯一清理依据。
4. 浏览器异常退出/网络静默断开由 Control Plane 主动 ping/pong 判定；收到有效 pong 后才为该终端向 Agent 续租，不能仅因服务端还在发送 ping 就续租。建议 15 秒检测，终端租约 60 秒；无有效续租后 Agent 本地终止 PTY。Control Plane 进程崩溃、Agent 到中心链路中断、Agent 重启时同样不会留下可恢复的终端。
5. 终止过程关闭 PTY、通知其管理的 Shell/前台程序，给短暂退出时间，再回收仍受其管理的进程与资源；清理必须幂等，不能按程序名误杀节点其他任务。tmux、nohup 等明确脱离终端的后台程序可独立存在，按正常终端语义处理，不承诺关闭网页即删除这些后台会话或任务。

这里的心跳只判断“浏览器是否仍连接”，**不是命令空闲超时**。网络闪断一旦造成连接断开，旧终端会结束，页面也不能重新接回；这是取消恢复功能后的明确取舍。

## 6. 文件传输细节

### 6.1 浏览与路径

Control Plane 固定节点身份，不接受浏览器冒用其他节点的路径上下文。Agent 负责解析路径、列目录、检查权限与文件类型；路径可以越出工作空间，目录软链接可指向其他可访问路径。列表结果只返回文件元数据，不读取文件正文；显示隐藏文件，浏览/下载只要求对应读取权限，不能复用工作空间验证中的“必须可读写”条件。普通文件操作开始时重新检查路径和文件描述符，避免用户浏览后文件已变化却继续使用旧结果。

下载只读取有限大小的普通文件，打开后确认文件描述符的类型、大小和身份，并在暂存前后核对大小、修改时间等变化；发现变化就失败，避免交付常见的混合版本。该检查不等于文件系统快照，本期不提供边写边下载的强一致快照。上传在已解析的目标目录创建不可预测名称的临时文件，核对字节数与 SHA-256 后提交；临时文件与目标位于同一文件系统，最终文件以原子重命名方式出现，失败时清理临时文件。上传不能覆盖目录、特殊文件或最终路径上的软链接；需要写链接指向的普通文件时，先进入真实目录再上传。

临时文件使用 `0600`；新文件提交时应用 Agent 用户的正常 umask，覆盖现有文件时保留其基本 Unix 权限与归属，无法保留时明确失败，避免上传一个文件后意外改变原有权限。上传不承诺保留浏览器文件的可执行位、ACL、扩展属性或修改时间，此类操作交给 Shell。存在目标文件时遵循用户已确认的冲突规则，不能无提示覆盖。上传与下载都不需要 Shell 解析路径，路径作为数据传递，避免命令拼接问题。

### 6.2 续传、下载与错误

本期断点续传只覆盖**同一页面仍打开、同一任务仍有效**时的网络闪断。浏览器上传使用 `File.slice()` 分片，失败后查询 Control Plane 已确认 offset，再继续发送当前文件；浏览器不能把整文件读进内存。例如一个 500 MiB 文件已确认收到 300 MiB，网络恢复后从确认位置继续，最多重传尚未确认的分片。关闭或刷新页面后不保留这个续传入口；再次选择文件会创建新任务。

Control Plane 到 Agent 的拉取、Agent 到 Control Plane 的下载暂存同样按各段链路自己的 offset 重试，并在完成前核对长度与 SHA-256。续传只能发生在同一尚有效的任务内，且再次验证节点、路径和文件身份；源文件已变化就失败，不能把两版内容拼在一起。网络错误采用有上限的退避重试，页面显示“连接中断，正在尝试续传”与已确认进度；权限、空间、内容校验和文件变化等业务错误不无限重试。

可靠性要求：同一任务的分片写入串行；完整写入分片后才确认 offset；确认响应丢失时客户端先查询真实 offset，不重复追加字节。浏览器以有界分片计算校验值，控制面核对分片及最终暂存文件，再由 Agent 核对整体 SHA-256；节点下载则由 Agent 提供哈希、控制面核对。重复分片要核对内容，不能仅凭位置当作相同数据。暂存文件的实际长度与记录不一致时先核对并修正或明确失败，不能跳过缺失数据。中断后的 SHA-256 可通过重新流式读取已有前缀重建，不要求序列化哈希内部状态。

取消后的迟到分片或 finalize 必须拒绝，Agent 上的最终提交与取消串行处理。取消到达时文件若已提交，保留结果并报告已完成，不能回滚或删除目标；若断线导致无法判断提交是否完成，显示“提交结果不确定，请检查目标文件”，不能声称“取消后没有写入”。这是原子写入的确认可能丢失时的明确边界。

下载准备完成后，浏览器通过已认证的 HTTP 端点获取附件式响应。暂存文件作为不可变快照，服务端提供 `Range`、`If-Range`、`Content-Range`、`Content-Length`、`ETag`、`Content-Disposition` 及正确的 206/416 响应，不进行改变文件字节表示的自动压缩，供浏览器管理保存位置、进度和可能的断点续传；本期不依赖 Chrome 专有的文件写入 API，也不承诺 Chrome 必定自动续传。服务端的 Range 能力只在任务有效期内提供，所属页面关闭或刷新后失效。Control Plane 只能报告自己已完整暂存文件与已开始响应，不能从 HTTP 响应结束推断用户磁盘写入成功。

准备完成但未请求下载的文件设有有限保留窗口，建议 30 分钟；过期后显示“准备文件已过期，请重新下载”。正在发送或重试的健康传输不因这个等待窗口到期而被删；下载响应结束后可以短时保留同一任务的快照供浏览器重试，但仍受页面租约、总配额与清理期限约束。任务结束且临时文件清理成功后删除清理用元数据，不积累历史文件任务。

前端区分浏览、等待节点、浏览器上传、Agent 拉取/推送、校验、等待用户下载、失败/取消等阶段；每项显示已确认字节数与总量。对节点离线、权限不足、文件变化、同名冲突、空间不足、哈希不符、过期及网络中断分别给出可理解的提示。节点暂不支持 capability 时禁止入口并给出升级提示。

### 6.3 页面关闭与失联清理

文件管理页使用一个轻量控制连接维护本页活动任务的租约；页面实例 ID 只存在当前页面内存中，刷新后生成新 ID，不能用新页面接管旧任务。页面关闭/离开的通知用于快速取消，后台租约超时作为兜底，不能只依赖页面退出回调。

文件控制连接允许同一页面在短暂断网后、租约过期前重新连接；这是当前任务的重试，与终端不允许重新接入的规则分别处理。建议页面租约为 60 秒，重试不延长没有有效心跳的租约；页面在后台但连接健康时可继续。到期后 Control Plane 停止任务、关闭仍在发送的下载响应、撤销任务令牌，并通知 Agent 取消。Agent 也保留任务超时和失联清理，防止控制面的取消通知未送达。清理允许幂等重试，取消后不提供继续入口。

管理员会话过期、注销或撤销也停止其活动文件任务。短时 Agent 任务令牌可在任务与页面仍有效时续期，过期不能迫使正常的慢速 1 GiB 传输从头开始；已取消任务不能换取新令牌。传输进展超时与页面失联超时分别处理，校验阶段也继续维持页面/任务租约。

## 7. 权限、资源与兼容

- 远程 Shell 等于允许已登录管理员以 Agent 的系统用户身份执行命令。界面首次使用时明确展示该用户；浏览器终端 WebSocket 必须校验会话 Cookie 与 Origin，Cookie 不转发给 Agent。节点凭证只用于 Agent 到 Control Plane，短时文件任务令牌不能用于其他任务或 Shell。
- Control Plane 只中转终端输入/输出，不写命令内容和终端画面。文件暂存内容仅保留到传输/下载所需的短时窗口；备份与日志不能无意长期留存临时文件。对外错误不回显节点凭证或任务令牌。
- 同一节点允许多个终端，但设置可配置的活动 PTY 上限；达到上限时明确拒绝新开，不挤掉现有终端。建议初始为每节点 8 个 PTY、每节点 2 个活动文件任务、分片 1 MiB；批次其他文件在当前页面内排队，不把整个批次同时灌入暂存。总暂存配额和磁盘保留余量在实施时按部署容量设置，不允许无界占用。终端和文件任务不进入 Codex Run 队列，也不占用 `maxConcurrentRuns`，但要限制各自资源，避免影响现有 Codex 任务和 Agent 心跳。
- 建议选用 `@xterm/xterm` 和 `@xterm/addon-fit` 渲染浏览器终端、`node-pty` 创建 Linux/macOS PTY。文件传输优先复用项目现有 Fastify、Node 流、HTTP Range 和分片 offset 模式；本期不接入完整文件管理器或另起 tus/Uppy 服务。
- 原生 PTY 依赖须按实际发布的操作系统、CPU 架构及 Linux libc 类型构建或安装，不能把一台构建机生成的二进制当成通用 Linux/macOS 包。每种宣称支持的产物都要运行启动 Shell、输入输出和 resize 的安装后冒烟测试；失败的 Agent 不报告终端 capability。当前 `--ignore-scripts` 打包流程需要为该依赖调整并纳入发布验证。
- 本地登记节点显示 Linux x64 与 macOS ARM64，可作为首批真实验证目标；实施前再核对目标节点的系统与 Node.js 版本，其他架构单独验证。原生模块产物按 OS/架构选择，首期以项目使用的 Node.js 24 为验证基线，不假定同一原生二进制支持任意后续 Node.js 版本。模块加载失败只使终端能力不可用，不得带崩 Agent 或已有 Codex 功能。
- 原有单一通用 Agent 压缩包需调整为可识别平台/架构的产物，节点接入的下载界面相应提供选择，继续显示独立 Agent 版本、大小与 SHA-256。优先在构建环境准备好原生依赖，不要求用户首次打开终端时临时安装编译器。Linux 工作区的验证不能代替 macOS 安装和 PTY 运行验证，发布前需要对应系统的实际环境。
- 新 Agent 在握手中分别报告 `terminal_pty_v1`、`node_files_v1`。只增加旧端不会收到的新消息类型及 capability 守卫，优先保持现有协议主版本兼容；若最终必须改变旧消息含义，再评估协议主版本升级。Agent 运行代码和安装内容会变化，实施时需按项目规则独立升级 Agent，并验证各目标系统的原生模块打包产物。

## 10. 已确认的产品细节

以下产品决定于 2026-09-30 经用户确认：

1. 上传同名文件：先预检整批冲突，用户一次确认后才允许覆盖；发现目标状态已变化时拒绝该项。
2. 关闭/刷新文件管理页：未完成传输结束并清理临时内容；页面仍打开期间允许自动重试与 offset 续传。已成功写入节点的文件不回滚，应用不能撤回已经交给浏览器的字节。
3. 终端打开方式：每次打开独立浏览器标签页，同一节点允许多个，每次均为新终端，关闭标签页后结束对应终端。
4. 文件规模：本期保证单文件最大约 1 GB 的正常上传和下载，设计上采用 1 GiB 的明确上限，超过上限时提前提示并拒绝传输。
5. 文件管理打开方式：独立浏览器标签页，绑定一个节点；原聊天页切换节点不影响该页传输，关闭文件页结束其未完成任务。
6. 下载进度与保存：网页显示节点到 Control Plane 的准备进度；最终下载和保存交给 Chrome 下载栏。本期不实现网页自主下载器，不把准备完成或请求下载当成文件已保存。

## 11. 最终下载进度方案

本期已确认采用 Chrome 原生下载。网页自主下载作为已评估的替代方案记录，不属于本期实现范围。网页可以显示最终下载进度，但普通网页不能直接读取 Chrome 下载栏的实时进度。两种方案的区别如下：

| 方案 | 网页显示 | 最终保存与进度 | 实现要求 |
| --- | --- | --- | --- |
| Chrome 原生下载 | 节点到 Control Plane 的已确认准备进度；校验阶段；准备完成后的下载提示 | Chrome 下载栏管理 | 网页不声称文件已保存；提供正确的 HTTP Range 响应及任务清理 |
| 网页自主下载 | 准备进度，以及 Control Plane 到用户电脑的传输字节进度 | 网页读取响应流并通过 Chrome File System Access API 写入用户选定的文件 | HTTPS、用户操作触发保存选择与授权；另行处理拒绝授权、写盘失败、取消、重试及最终关闭写入流 |

网页自主下载可以边接收边写入，不必将 1 GiB 文件全部放入内存；但需要维护网页下载器的完整生命周期，不能只添加一个进度条，也不能同时继续依赖 Chrome 下载栏管理同一次传输。字节接收完成后仍须完成本地写入的提交，才可显示保存成功。

按本期简单、稳定的目标，采用 Chrome 原生下载：网页显示“正在准备下载（已传输字节 / 总大小）”，准备完成后显示“已请求浏览器下载，请在 Chrome 下载栏查看进度”。准备进度达到 100% 只表示文件已在 Control Plane 暂存并通过校验，不代表已经下载到用户电脑。浏览器阻止下载时提供再次点击下载的入口与提示，不能将下载请求当成保存成功。

Control Plane 提供 Range 支持，但 Chrome 中断后可能需要用户手动继续或重新下载，不保证网页控制的全流程自动续传。该边界属于已确认的 Chrome 原生下载方案。
